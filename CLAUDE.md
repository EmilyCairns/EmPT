# Notes for AI assistants working on EmPT

- Before changing anything visual, read `DESIGN.md` and follow it. It is the owner's design system.
- All colours, font sizes, spacing, radii, shadows and widths come from `design-tokens.css`. Never put raw values in `styles.css` or inline styles in `app.js`; add a token instead.
- After a visual change, check `styleguide.html` and the app at phone (390px) and desktop widths (the app is light theme only).
- Database access rules live in `supabase/schema.sql`. Clients must only ever see their own data. The one exception is **Team wins** (`community_members`, `wins`, `win_reactions`): clients who opt in share their first name and wins (PBs, streak seals, finished programs, workout milestones) with other clients. Never add a client to `community_members` yourself, never post a win for a client who isn't in it, and never put anything from consult notes, health forms, check-ins or feedback in a win or shout-out.
- When creating workouts for the trainer directly in Supabase, always insert them as drafts (`is_draft = true`, the column default) and never publish them unless the trainer asks. Read the client's `client_notes` and `client_health` (their own health form: APSS screening, injuries, medical, pregnancy, goals, lifestyle, availability) first and plan around injuries and conditions. If `screening_flag` is true, remind the trainer they need GP clearance before training. Also check `client_maxes` (rep maxes), recent `set_logs` (what they actually lifted) and `workout_feedback` (their comments and things like period, night shifts or poor sleep that affected sessions) to set sensible loads. Treat feedback as private health information: use it for planning, never quote it anywhere the client or others might see.
- Workout exercises are a JSON array of objects with string values: `{ name, exercise_id, sets, reps, pct, rm, load, rest, notes }`. Use names from the `exercises` library and set `exercise_id` to the matching id (add new exercises to the library first). For percentage loads set `pct` (e.g. "70") and `rm` (e.g. "1" for 1RM); leave both "" otherwise. The app shows the client the weight. Write `rest` in a form the rest timer understands ("90s", "2 min", "1:30"). For barbell lifts, make sure the library exercise has `is_barbell = true` (null means "guess from the name") so the client sees the plate calculator.
- Programs (`programs` table): a block of the same workouts every week. `templates` is a JSON array with one `{ title, notes, exercises }` per training day (same exercise format as workouts). A program's `notes` is shown to the client as the program's aim. Create programs as `status = 'draft'` and never send (`'offered'`) or schedule them unless the trainer asks. `schedule_program()` turns a program into dated workouts (`program_id`, `program_week`, `planned_date`); after that, adjust a single week's loads by editing that week's workouts. Clients move workouts with `move_workout()` (up to 14 days from `planned_date`, not into the past).
- Sessions (`sessions` table) are booked by the trainer. Never cancel or delete a session unless the trainer asks; cancel through `cancel_session()` so the client is sent a message.
- Rest weeks (`excused_weeks`: `client_id`, `week_start` = a Monday) pause a client's streak. Only add or remove them when the trainer asks.
- Any database change made directly in Supabase must also be added to `supabase/schema.sql`, so the file always matches the live database.
